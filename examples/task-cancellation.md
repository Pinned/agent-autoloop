# 取消整件任务示例

先用本人业务查询核对任务编号、原始需求、关联执行与卡片，不拿轮次编号当任务编号。本人操作：

```text
POST /v1/tasks/42/cancel
Authorization: Bearer <本人已有密钥>
Content-Type: application/json

{"reason":"本人已决定不再需要这件任务"}
```

返回 `cancelling` 说明意图已记录，但还在等执行退出；这不是失败，也不是成功完成。不解除未知执行的占用，不自动重新发任务。返回 `cancelled` 才说明全部执行已退出、该任务遗留卡片已因取消终结、该任务占用已释放。原回答和事实历史保留。

回答选项里的“取消”仍只是回答。停止一轮、手动释放占用都不等于取消任务。旧轮次没有明确业务身份时不能使用该入口猜测关联。新客户端与中台需同步升级，见[协议](../docs/protocol.md#整件任务取消)。
