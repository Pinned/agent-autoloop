# 桌面初始化桥开发说明

当前桥提供四种固定操作：`setupStatus()`、`checkBuiltinAgents()`、`initHub()`、`joinWorker({ url, worker, key })`。今天与设置页提供“配置此电脑”入口；只有用户点击后才核查本机配置。

## 配置此电脑

引导分为选择角色、配置本机、检查与确认三步。中台＋本机 worker 使用默认本机回环端口 3350；纯 worker 填中台地址、本机名称，并在最后确认前输入加入密钥。安装检查由用户主动触发，不检查登录或远端连接。未发现安装允许继续；安全结束的安装检查失败可由用户明确确认跳过。

保存成功只表示本机配置保存，本次操作不启动服务。已有配置只读显示角色；无效或未完成配置需人工检查，不提供覆盖、切角色或重置。写入失败先显式核查本机状态，不能直接重试；无法确认完成时本次会话锁定。

密钥不进入页面控制器草稿、状态、URL、存储或错误文本；桥交接后立即清空 password 输入，返回、取消或离开引导也清空。主题只更新根节点，不重建表单。不保证 JavaScript 内存清零。五页业务数据仍待接入，配置成功不代表已可接任务。

## 安全边界

- 业务由已验证的独立官方 Node 执行，Electron 主进程不读取业务配置内容。桥仅使用已有运行时缓存，不自动下载；正式打包资源未交付前返回不可用。
- 开窗不检查、初始化或启动业务；开发数据仅位于显式临时 `DESKTOP_HOME` 的 `runtime-home`，不迁移真实 CLI 数据。
- 安装发现仅检查固定系统路径里的 Claude/Codex 程序文件，不运行 shell、Agent 或登录命令，不加载业务 HOME 的插件覆盖。结果 `not-found` 只表示受限范围内未发现，用户级安装可能漏报；登录始终 `unknown`。
- 初始化使用默认回环端口，允许没有发现 Agent。加入仅保存 worker 配置，不验证中台可达性或凭据有效性，不连接远端。
- 已有或生成的凭据不返回页面。加入时用户输入的密钥通过固定 IPC 和子进程 stdin 保存，不进入命令参数、环境、日志或响应。
- 初始化／加入持有现有独立运行锁，可能产生 `up.lock.db` 和持锁期间的自有 `up.pid`；worker-only 不创建中台数据库、master key、规则或系统服务。

## 生命周期

设置与业务启动在首次异步等待之前互斥预约。退出会封闭新操作、等待设置完成，再安全停止业务。初始化和加入不可强制取消；结果、退出或资源清理无法确认时进入 `unknown`，保留现场，禁止重复设置、启动和退出。不会发送强杀信号、接管外部进程或自动删除残留锁。

本阶段不提供恢复 UI，也不意味着运行中的 Agent 已登录。进程组确认不是操作系统沙箱，不保证主动逃逸进程组的后代已停止。

## 验证范围

契约、驱动、调用器和控制器测试使用临时 HOME、合成密钥与假进程；测试安装发现不依赖机器实际安装。资源测试验证缓存缺失时零下载。首启控制器使用 fake bridge 检查状态与单飞；浏览器 DOM 验证也不连接真实桥。这些检查不是实际 Agent 登录、远端连接或真实 Electron 业务生命周期 E2E，不能互相替代。
