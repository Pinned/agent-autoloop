# 桌面初始化桥开发说明

当前桥提供五种固定操作：`setupStatus()`、`launchStatus()`、`completeSetup()`、`initHub()`、`joinWorker({ url, worker, key })`。执行机页的“配置此电脑”和设置页的“查看本机配置状态”打开同一张引导页；只有用户点击后才核查本机配置。

## 配置此电脑

引导分为选择角色、连接两步。中台＋本机 worker 在保存时另行分配一个本机回环端口（避开中台文档默认的 3350，首次配置不占用终端中台会用的地址），保存后由“完成首次配置”请求启动。纯 worker 填中台地址、本机名称与加入密钥，点击即连接并保存。

连接与保存是一件事：主进程在任何写入之前先验证这把密钥能否以该本机名称操作该中台（协议阶段要求中台宣告 `credentials.worker.v1`，随后读取 worker 握手）。验证不通过就不写盘，因此那三种失败（`connection-failed`、`credential-rejected`、`identity-mismatch`）可以保留草稿、直接改完重试；其余写入失败仍先核查本机状态，不能直接重试；无法确认完成时本次会话锁定。中台＋执行机的 owner 凭证来自本机 CLI 配置，每次启动都由接入控制回答“能否操作该中台”，保存时不另做一次远端校验，否则仅因中台暂时停止就会把人挡在门外。

保存成功只表示本机配置保存，本次操作不启动服务。已有配置只读显示角色；无效或未完成配置需人工检查，不提供覆盖、切角色或重置。

密钥不进入页面控制器草稿、状态、URL、存储或错误文本；桥交接后立即清空 password 输入，返回、取消或离开引导也清空。主题只更新根节点，不重建表单。不保证 JavaScript 内存清零。配置成功不代表已可接任务。

## 安全边界

- 业务由已验证的独立官方 Node 执行，Electron 主进程不读取业务配置内容。桥仅使用已有运行时缓存，不自动下载；正式打包资源未交付前返回不可用。
- 开窗不检查、初始化或启动业务；开发数据仅位于显式临时 `DESKTOP_HOME` 的 `runtime-home`，不迁移真实 CLI 数据。
- 安装发现按用户登录 shell 解析出的 PATH 查找 Claude/Codex 程序文件，解析不到时才退回固定系统路径；不运行 Agent 或登录命令，不加载业务 HOME 的插件覆盖。没找到只表示这份 PATH 上没有，用户级安装仍可能漏报；登录始终 `unknown`。
- 初始化自动分配回环端口（显式端口覆盖除外），允许没有发现 Agent。加入先以只读握手验证加入密钥能否操作该中台，验证通过才保存 worker 配置；不启动中台、不创建业务数据。
- 已有或生成的凭据不返回页面。加入时用户输入的密钥通过固定 IPC 和子进程 stdin 保存，不进入命令参数、环境、日志或响应。
- 初始化／加入持有现有独立运行锁，可能产生 `up.lock.db` 和持锁期间的自有 `up.pid`；worker-only 不创建中台数据库、master key、规则或系统服务。

## 生命周期

设置与业务启动在首次异步等待之前互斥预约。退出会封闭新操作、等待设置完成，再安全停止业务。初始化和加入不可强制取消；结果、退出或资源清理无法确认时进入 `unknown`，保留现场，禁止重复设置、启动和退出。不会发送强杀信号、接管外部进程或自动删除残留锁。

本阶段不提供恢复 UI，也不意味着运行中的 Agent 已登录。进程组确认不是操作系统沙箱，不保证主动逃逸进程组的后代已停止。

## 验证范围

契约、驱动、调用器和控制器测试使用临时 HOME、合成密钥与假进程；测试安装发现不依赖机器实际安装。资源测试验证缓存缺失时零下载。首启控制器使用 fake bridge 检查状态与单飞；浏览器 DOM 验证也不连接真实桥。这些检查不是实际 Agent 登录、远端连接或真实 Electron 业务生命周期 E2E，不能互相替代。
