# agent-autoloop 交互原型

## 打开方式

直接用现代浏览器打开同目录 `index.html`，保留 `style.css` 和 `app.js` 在同一目录。支持 `file://`，无需框架、依赖、安装或本地服务。建议 Chrome / Edge / Safari 的近期版本。

主窗口设计尺寸为 **1080 × 760**；在更小窗口中自适应，内容区独立纵向滚动。手机宽度下导航变为图标，任务行隐藏成本列（详情仍可查看成本）。

顶栏始终提示“交互原型·假数据，不连接真实服务”。所有操作都只是网页内部模拟。

## 建议演示路径

1. **首次使用**：选择“中台 + 本机 worker” → 配置示例地址 → 模拟连接检查 → 模拟环境检查 → 进入指挥台。也可以选“纯 worker”体验受限视图。
2. **今天**：查看四项概览 → 对 #41 选择“精简摘要 / 深度分析”或填写自定义回答 → 任务变为运行中。对交付通知点击“通知结案”，任务仍留在完成列表。
3. **任务与详情**：搜索关键词或编号，按状态 / 类型筛选 → 点击任务 → 查看时间线、轮次、输入、成本与执行信息。运行任务可“模拟完成”；排队任务可“模拟开始执行”。
4. **更正和停止**：在详情提交更正 → 原轮次保留结束记录，新增下一轮并入队，绝不把重跑写成同一轮。停止操作有二次确认，保留时间线和成本。
5. **交付反馈**：完成任务详情中点击“提交交付反馈”，选择评价类型并填写内容。反馈不触发执行；需要改目标时用“提交更正”。复制交付仅复制示例文字，浏览器不允许剪贴板时提供手动复制弹窗。
6. **新建**：侧栏或页面按钮 → 选择任务类型、填写标题和详情 → 查看 Agent / 本机 / 目录路由预览 → 创建排队任务。开发任务示例路由到 Codex，其余路由到 Claude。
7. **自动化**：新增 / 编辑规则 → 切换“定时 / 事件”，观察动态字段 → 选择 Agent 与 Prompt / Skill → 填写目录和输入。空字段、相对目录、非法 Skill 名称会显示错误。没有规则启停开关，保存不建立真实调度。
8. **执行机**：查看本机和远程假设备的在线 / 离线状态 → 查看分配任务 → 本机环境模拟检查。环境缺失可模拟修复，不安装程序。
9. **设置**：分别编辑 Agent、来源、通知通道、连接与通用行为。通知测试仅弹出页面提示。通用页切换深色、浅色、跟随系统。
10. **纯 worker**：设置 → 角色连接 → 切换角色。只保留本机任务、本机环境、连接与设置；无今天、全局新建、自动化、来源、通知通道管理，也无任务更正 / 停止 / 决策 / 交付反馈入口。本机“开始执行 / 完成”属于受限演示推进动作。
11. **桌面行为**：顶部“autoloop”打开菜单栏模拟弹窗。红色关窗按钮模拟关窗驻留，黄色按钮模拟最小化，绿色按钮切换网页窗口高度。菜单可恢复窗口；“真退出”须确认并模拟停止本机未完成任务，不影响远程任务。恢复窗口不会悄悄重跑已停止的轮次。
12. **异常与空状态**：右上切换正常 / 空状态 / 断线 / 环境缺失。断线展示快照并阻止任务与中台配置提交；“模拟重连”恢复正常。环境缺失阻止本机 Claude 任务开始执行。空状态隐藏任务、规则与通知，可新建任务 / 规则返回正常。

底部“重新体验首启”保留当前数据，重走引导；“重置演示”确认后恢复预设数据与首启状态，但保留主题。

## 实现范围与边界

- 仅 HTML / CSS / JavaScript，自包含、无外部字体、图片、模块或网络依赖。
- 假数据状态涵盖首启、角色、任务、轮次、反馈、规则、通知和配置；操作后列表、详情、计数同步变化。
- 主题和原型状态仅保存在本原型专用的两个 localStorage 键：`autoloop-prototype-theme` 与 `autoloop-interaction-prototype-v1`。不清空其他站点数据；浏览器禁止存储时仍可进行当次演示。
- 演示令牌输入不保存，实际状态始终使用 `demo-token`。其他配置文本会作为原型状态保存，**请勿输入真实令牌、Webhook 或私密内容**。
- 角色隔离用于产品演示，不是安全鉴权，不存在真实 owner 提权或后端权限校验。
- 不连接中台、Agent、飞书或其他服务，不运行进程，不访问工作目录，不读取安装情况，不发送真实通知，不建立定时任务，不控制系统窗口或后台驻留。
- 不包含插件，不暗示后端已经实现自动化编辑或启停功能。
- 模拟任务时间、成本、执行结果与设备心跳均非真实数据。更正显式开启新轮次；回答决策保持当前轮次；交付反馈不新增轮次。
- 所有弹窗支持 Esc、背景区域点击关闭、Tab 焦点循环；错误带可见提示与字段焦点。原生 dialog 管理背景不可交互和焦点返回。

## 测试建议

- 按上面的路径分别验证 owner / worker；确认 worker 无全局权限入口且只显示本机任务。
- 在新建、更正、反馈与规则弹窗直接提交空表单，验证提示；尝试相对路径、带空格 Skill、无效中台 URL。
- 对 #41 自定义回答后确认仍是第 1 轮；提交更正后确认新增第 2 轮；停止后确认状态及历史保留。
- 断线状态提交任务 / 回答 / 更正 / 规则应被拒绝，环境缺失时本机 Claude 任务不能启动，模拟修复后可启动。
- 切换两种规则触发方式，确认隐藏字段不参与验证；新增、编辑后返回列表检查内容同步。
- 检查桌面菜单、关窗驻留、恢复与真退出确认；停止操作均不接触真实进程。
- 用键盘打开弹窗，验证首个输入焦点、Shift+Tab / Tab 循环、Esc 关闭及焦点返回；检查复制受限时的备用弹窗。
- 在 1120 × 826 浏览器视口验证 1080 × 760 主窗口，在 1080 × 760、390 × 844 视口验证所有页面和详情无横向溢出。
- 分别查看深浅色；“跟随系统”随系统偏好变化。刷新后主题和假数据保留；重置演示不会清除其他 localStorage。
- 浏览器开发工具 Network / Console 中确认没有外部请求或脚本错误。

已用浏览器直接打开本地文件验证：首启、任务回答、更正轮次、新建、停止、完成、反馈、规则动态字段及校验、执行机任务范围、worker 权限、异常状态、主题、驻留 / 退出、Esc 和桌面 / 手机横向溢出；JavaScript 通过 `node --check`。这些是原型级检查，不是业务或真实服务测试。
