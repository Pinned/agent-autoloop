# 桌面 App 开发范围

桌面版正在分步开发，**尚未交付可用于真实业务的 App**。已确认的交互基准是 [`mockups/app-prototype/`](../mockups/app-prototype/README.md)；另外保留 v1/v2/v3 两页视觉候选，最终采用 v1，并支持深色、浅色和跟随系统。

## 当前可运行范围

`desktop/` 已有开发用 Electron 窗口：五页导航、深色/浅色/跟随系统、关窗菜单栏驻留和退出确认。业务页面仍为明确的待接入状态；本机运行服务由应用菜单或托盘中的显式操作启动，不会因开窗自动启动，也不会连接或接管现有 CLI 服务。这不是已交付的业务 App。

开发时先在仓库根目录安装独立依赖，再运行隔离的窗口检查：

```bash
npm --prefix desktop ci
npm --prefix desktop run typecheck
npm --prefix desktop test
npm --prefix desktop run runtime:check
npm --prefix desktop run smoke
```

`runtime:check` 会下载固定版本的官方 Node 24.22.2，按官方 HTTPS 清单比对 SHA256，然后在含空格的临时资源目录和隔离 HOME 中验证原始 TS、SQLite 自定义函数、事实持久化和动态插件。没有进行签名验签；macOS arm64 已实机验证，其他架构不能仅凭目标配置称为验证通过。Linux 目标仅供 CI 验证，不代表提供 Linux 桌面安装包。

macOS 窗口检查使用自动创建并清理的临时数据目录，不发送通知。手动启动也必须指定临时目录：

```bash
DESKTOP_HOME="$(mktemp -d)" npm --prefix desktop start
```

手动退出后可自行清理该临时目录。开发版只使用 `DESKTOP_HOME/runtime-home` 作为业务目录，不读取或迁移 `~/.agent-autoloop`，也不会自动初始化。没有配置时仅显示未配置提示；本期尚无首启设置页面，请勿把真实配置或密钥复制到开发测试目录。

运行进程的排空接口与退出门禁正在验证：无法确认进程停止或临时资源清理完成时，应用保持驻留，不强制退出。已确认所有权的资源清理失败可以重试；资源身份未能确认或路径已被替换时拒绝自动删除，需要人工检查。离线结果保留为待同步，不冒充已提交成功。尚未提供安装包，也未完成真实 App 的业务生命周期冒烟验证。

## 产品边界

- Electron App 自己管理中台和执行机运行进程，支持“中台 + 本机执行机”和“纯执行机”，不是遥控另外安装的系统服务。
- Electron 负责窗口、菜单栏、凭据与有限桥接；业务仍通过中台协议执行。内核不认识 Electron，不增加运行时依赖。
- 安装包目标为 macOS `.app` / `.dmg`，自带验证通过的 Node 24 与 TS 运行资源；不要求用户另装 Node。Agent CLI 仍需安装并登录。首期不承诺 Windows、自动更新、签名或公证。
- App 使用独立数据目录，不自动导入 CLI 数据，不安装 launchd/systemd，不修改全局 Skill 链接。CLI 安装与运行方式继续保留。
- 关窗只是隐藏窗口，运行进程继续工作；真退出确认后停止本机正在执行的 Agent，保留记录及待同步回执，不取消远程任务和中台尚未领取的队列。
- 纯执行机仅展示本机执行摘要、环境与连接，不保存 owner 密钥、不读取全局任务、不提供全局管理操作。摘要不等于中台队列。
- 本期不开发插件管理页面或新的插件机制；现有 Agent、来源、通道插件加载路径和协议继续保留。

## 原型与真实功能的区别

原型是假的演示状态机。正式实现保留布局和操作组织，但不能复制下列假行为：

| 原型表现             | 正式实现                                                          |
| -------------------- | ----------------------------------------------------------------- |
| 回答后原轮恢复执行   | 提问轮已结束；回答产生下一轮或合并已有排队轮，尽量接续会话        |
| 任意任务都能更正     | 只有存在可接会话且规则/Agent 匹配的轮次可更正；旧轮记录保留       |
| 点击停止即显示已停止 | 已领取轮次先显示正在停止，等待执行机确认进程组结束                |
| 模拟开始、完成、修复 | 不出现在正式界面；执行由 worker 和 Agent 回执驱动，体检不安装程序 |
| 固定三种任务路由     | 候选和路由来自真实 local 规则，输入不能决定 Agent、目录或权限     |
| 固定成本和比例       | 使用真实 usage；未上报不当作零，不估算输入/输出比例               |
| 默认目录属于 Agent   | 工作目录属于规则；编辑保留 group、parallel、tell、emits 等字段    |
| 交付反馈只改网页     | 新增 owner 限定的只记录事实能力，不更正、不派发，不改变轮次结局   |
| 远程机器平台和修复   | 只展示已有真实心跳与任务分配，不编造远程环境信息                  |

“任务”在界面上表示事项，历史轮次对应真实 run。失败重试次数不是轮次；同标题不代表同事项。搜索与筛选必须覆盖服务端查询范围，不能在最近 60 轮上过滤后称为全局搜索。

## 本机任务入口协议

桌面规则与任务桥接 DTO 为版本 2，主进程与 renderer 同步校验；HTTP 仍兼容已有网页的 `GET /v1/ui/rules` 与数组 `PUT /v1/ui/rules`。列表可以为空，表示移除所有 local 入口，不移除其他来源规则。

- 入口字段为 `name/types/to/cwd`，可选 `prompt/skill/parallel/group/tell/emits`；`emits` 严格为 `{source,types}`，来源必须已登记且不能为保留的 `schedule`。表单可保留、修改或清除高级字段。
- 未声明 `group` 时跟随规则名称，未声明 `tell` 时使用 `needed`。显式 `group` 即使等于旧规则名称也会保留，不从解析后的默认值反推用户意图，不新增 `defaults` 元数据。
- 替换原有 local 插槽，不挪动非 local 规则；新增项放在最后一个 local 插槽后，无原有 local 时追加。保存对同一份文件执行一次读取、合并、完整校验和原子替换，缺失的 local 来源一并补齐。无效来源引用不落盘。
- 候选规则支持 `*` 和 `x.*`；真实事件仍只接受小写字母开头、最长 64 字符的具体类型。选择通配模式必须手动填写匹配的具体类型，不自动生成后缀；最终路由以中台回执为准。
- 原始声明仅在完整校验且与中台已应用配置一致时用于编辑。坏磁盘或尚未生效的变更不混入旧运行配置。内核历史只保存解析后的有效值，未持久化原始声明；冷启动遇到坏磁盘且没有有效声明快照时明确拒绝编辑，不能无条件恢复历史显式字段。

本单元不提供 CAS 冲突保护、不提供写盘式“预览”，也不实现非 local 自动化编辑；`seq` 仍是日志序号，不是配置版本。规则专属版本和冲突保护在下一单元接入。

## 迭代顺序

每个小需求单独测试和提交：

1. 固定原型与产品范围（本阶段）。
2. 安全 Electron 壳、双主题导航及自带运行时兼容验证。
3. App 内运行进程管理、共享实例锁与受控安全退出。
4. 双角色首启和本机环境检查。
5. 今天页、卡片与实时连接。
6. 事项查询、任务列表及详情。
7. 真实新建、停止和更正。
8. 只记录的交付反馈。
9. 完整自动化编辑及保存冲突校验。
10. 执行机与完整设置。
11. 菜单栏及系统通知闭环。
12. macOS 安装包与分发验证。

未接通的入口保持明确的未完成提示，不用原型假数据冒充真实功能。各阶段验证使用临时数据目录、随机端口、假 Agent、假通道和假通知，不碰真实服务或付费调用。自动测试沿用 `node:test`，桌面窗口和安装包行为另做冒烟验收；打包完成不等于已签名或已公证。
