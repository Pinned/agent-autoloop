# 桌面 App 开发范围

桌面版正在分步开发，**尚未交付可用于真实业务的 App**。已确认的交互基准是 [`mockups/app-prototype/`](../mockups/app-prototype/README.md)；另外保留 v1/v2/v3 两页视觉候选，最终采用 v1，并支持深色、浅色和跟随系统。完整的交互设计原则、视觉令牌、组件模式与前端开发规范见 [桌面端 UI 交互设计与前端开发规范](desktop-ui-guide.md)。

## 今天页面自动刷新

「正在推进」卡片主数字使用既有快照 totals.running（已领取、运行中的轮次），同卡次级显示「排队中 N」，使用 totals.queued（排队轮次，包含等待重试的轮次，不另加 retrying）。两者均来自中台全部轮次投影的计数，不按业务任务去重、不从最多六条的推进预览或分页长度推算，也不把排队计入运行。零排队显示「排队中 0」；读取失败保留既有成功快照及错误提示，没有成功快照时不显示成功数字。旧响应缺 queued 沿用严格校验拒绝，不默认补零。本次不新增字段或改变协议、调度与跳转。

选中「今天」且窗口可见时，默认每 5 秒自动读取一次；其他页面、窗口隐藏、设置或重连页面覆盖时暂停。恢复前台时，距上次成功读取满 5 秒立即刷新，未过期等待剩余时间。请求不重叠，慢请求结束后再安排下一次读取；页面退出时清理定时器，已发出的请求可正常结束。页面不提供手动刷新按钮，也不显示刷新时间或数据时间；成功读取时隐藏空状态行，加载、错误和服务未启动提示仍保留。失败保留已有数据并显示错误，5 秒后再试。刷新只走既有只读接口，不改变业务状态。

## 整件任务取消

业务详情的「取消任务」与「停止执行」分开，原位确认说明并填写取消原因，不使用删除或前端隐藏替代业务收尾。确认经 owner 写入口 `POST /v1/tasks/<taskId>/cancel` 提交，IPC 的 action 为 `cancelTask`、身份为 taskId；不能把 runId 混入。取消入口不依赖轮次诊断读取；旧轮次及旧中台兼容路径不提供猜测关联的取消入口。

取消中/已取消以中台业务状态为准。提交只显示真实回执并重新读取；结果不明先重读，不自动重发。取消中禁止回答续办和更正；未知执行仍等待退出证明。已取消从 active 筛选排除，全部任务保留，显示「已取消」而非成功完成。停止一轮仍只表示本轮已停止。取消的原位说明、草稿和禁用规则遵循桌面 UI 规范，见[协议](protocol.md#整件任务取消)。

## 本人确认完成

业务任务详情操作区提供「本人确认完成」，原位展开验收原因表单，再点击「确认完成任务」提交。旧执行、兼容旧中台、已完成、取消中与已取消任务不提供该操作；填写或展开表单不发送请求。IPC 使用 `completeTask` 与 taskId，由主进程受控调用 `POST /v1/tasks/<taskId>/complete`，不读取前端密钥、不创建执行。成功后重新读取详情和当前筛选列表，显示本人完成原因及时间；失败只显示固定的对应阻塞原因，不关闭卡片、取消复查或释放占用。结果不明先重读，不自动重发。见[协议](protocol.md#本人确认完成)。

今天页「待你决策」的主入口使用本人状态查询确认的卡片可选 `taskId` 直接打开对应业务详情，并定位卡片编号对应的问题；不从标题、规则或执行编号推断任务。该字段为正安全整数或 null，严格 DTO 同步白名单，旧响应可省略；缺业务身份时明确提示而不展示无法执行的入口。今天快照只有有界标题与正文，没有完整选项及回答操作能力确认，因此全部使用详情回退，不展示原地回答表单。详情权威重读真实问题及当前状态，首屏未包含时沿既有有界时间线分页定位只读问题记录，不从历史状态补造回答权限；记录缺失、读取失败或达到预算时明确提示。复用现有任务/卡片草稿、独立提交与不确定结果显式核实；迟到的今天快照不授予回答权限。返回今天恢复原滚动位置，保留既有刷新、计数及写入保护约定。

今天页的正在推进列表沿同一 `GET /v1/state` 只读快照显示业务任务编号、固定首次事件名称、一行本轮触发描述和真实轮次状态（首次沿用原始详情）；回答、更正从可选 triggers 的真实本轮关联展示，回答包含问题标题、选项文字和文字补充，更正保留原文，多条明确总数，不猜跨轮卡片。旧中台缺 triggers 或本轮只有其他触发时沿用原始详情；旧记录明确显示执行编号，只称触发资料。缺资料显示未记录，确实空详情显示未填写，不用规则或执行摘要冒充需求。request 为可选白名单字段，名称/详情按 500/2000 码点严格校验，stopping 为可选布尔；旧 v3 响应兼容，IPC 仍严格拒绝其他字段和 getter。最多六条推进预览与原有卡片一起受 1.5 MiB 上限约束。长详情以纯文本单行省略，悬停保留快照内文本和截断提示；列表不额外查询、不暴露凭据链接、不改业务事实。明确带业务 taskId 的条目可点击标题、正文或非交互空白进入既有业务详情，标题支持聚焦与 Enter；控件、修饰键和文字选择不误跳，无身份旧条目不提供入口。返回回到今天并恢复滚动位置，写入中或结果待核实时保留既有保护。

五页之外，派发任务原位子页与托盘菜单同样是真实数据。派发得到明确接受回执后自动返回打开它的实际来源页，并清空已提交草稿与正文；失败或结果不明仍停留、保留内容，不自动重发。关闭子页不会重新缓存已提交内容。关窗只是收起到托盘，运行进程继续工作；退出确认后停止本机正在执行的 Agent。首启只有两步：第 1 步选角色（「中台＋执行机」在本机管理工作也由本机执行，「纯执行机」保存已有中台的连接配置、由这台电脑执行），第 2 步建立连接，连接成立后「完成」一次点击即写入自动启动策略并请求启动。第 2 步的形态由角色决定：中台＋执行机进入该步时立即读取本机 CLI 的配置并探测中台，期间只显示 Loading 条目且「上一步／完成」置灰；探测成功显示已连接并放开「完成」；失败时提示先启动中台服务后重试，此时只有「上一步」「重试」可用；CLI 未配置中台时，App 静默写入配置并启动内置中台，启动开始后「上一步」不再可用。纯执行机则是三个输入框（中台地址、本机名称、加入密钥）：点击「连接」先验证再保存，接受后角色即锁定，再点「完成」进入主页面。已有旧配置但没有启动策略的电脑不会被自动启动，也不被覆盖；`prepared` 中间态只在崩溃恢复时出现，此时页面只要求补写启动策略。中台角色每次启动都重新判断本机中台从哪来：CLI 配置指向一个中台时（无论是否正在运行），App 只在本机回环上探测并接入它，不启动第二个中台，也不提供启停；接入后中台不再应答时，界面切到重连页，可重新连接，或改用 App 内置中台。CLI 未配置中台、配置为纯执行机、配置不可信或未安装 CLI 时，App 静默启动内置中台。接入判断不看端口通不通：App 用本机 CLI 的 owner 凭证请求 `GET /v1/state`，中台返回 200 才接入，401/403 视为凭证被拒、重定向与超时都按未接入处理。因此接入成功同时说明这把 owner 能读该中台的数据，而不只是地址可达。「改用内置」只对本次会话生效：App 不保存这个选择，重启后仍按本机 CLI 的连接配置重新判断，因此想回到接入模式只需重启。`npm --prefix desktop run dist` 已能产出 arm64 `.dmg`，但不是已交付的业务 App：安装包是 ad-hoc 签名、未公证，也还没有在安装后的真实 App 上做过验收；业务生命周期冒烟目前只在隔离环境通过。

开发时先在仓库根目录安装独立依赖，再运行隔离的窗口检查：

```bash
npm --prefix desktop ci
npm --prefix desktop run typecheck
npm --prefix desktop test
npm --prefix desktop run runtime:check
npm --prefix desktop run smoke
```

`runtime:check` 会下载固定版本的官方 Node 24.22.2，按官方 HTTPS 清单比对 SHA256，然后在含空格的临时资源目录和隔离 HOME 中验证原始 TS、SQLite 自定义函数、事实持久化和动态插件。没有进行签名验签；macOS arm64 已实机验证，其他架构不能仅凭目标配置称为验证通过。Linux 目标仅供 CI 验证，不代表提供 Linux 桌面安装包。

macOS 窗口检查使用自动创建并清理的临时数据目录，不发送通知。手动启动也必须指定临时目录：

```bash
DESKTOP_HOME="$(mktemp -d)" npm --prefix desktop start
```

手动退出后可自行清理该临时目录。开发版只使用 `DESKTOP_HOME/runtime-home` 作为业务目录，不读取或迁移 `~/.agent-autoloop`，也不会自动初始化。没有配置时仅显示未配置提示，由首启流程写入；请勿把真实配置或密钥复制到开发测试目录。

首启期间，读取本机配置状态（`status`、`launch-status`）只读磁盘上的 `config.json`、`setup.lock`、`setup.pending.json` 与 `desktop-launch.json`，不等待内置运行时解压或校验。运行时准备只发生在真正写入配置（`init`／`join`）时，因此冷启动不会因为 53 MB 归档解压与 SHA256 校验而让界面停在「本机运行服务控制暂不可用」，也不会因此看不到角色选择页；配置读写仍由主进程内的单飞闸门串行化。

纯执行机的写入先验证再落盘：主进程在调用驱动之前，用中台地址与加入密钥确认这把凭证能否以所选本机名称操作该中台（协议阶段要求中台宣告 `credentials.worker.v1`，随后读取 worker 握手）。验证不通过就不写盘，界面因此可以保留草稿供修正后重试；中台＋执行机的 owner 凭证来自本机 CLI 配置，进入第 2 步时的只读探测（`connect`）就回答同一问题——读 CLI 配置、用 owner 凭证请求 `GET /v1/state`，既不写盘也不占运行锁，因此「完成」之前界面已经有连接成立的证据，保存时不再重复探测。

首启配置是独立页面，不是工作空间里的一块面板。窗口的第一帧带 `data-shell="checking"`：在启动记录给出答案前，左侧菜单不绘制，业务页也不绘制——菜单是一句承诺（"这些是本机能打开的页面"），未配置的电脑没有可承诺的页面。启动记录为 `complete` 或 `legacy` 时进入 `data-shell="workspace"`，菜单与业务页才出现；`first-run`、`prepared`、`recovery`、`invalid` 一律停在 `setup`，配置页独占整窗。读取失败（`blocked`）不当作"未配置"的证据，保留菜单——一次磁盘抖动不该夺走一台已配置机器的导航；写入结果未知（`unknown-locked`／`mutation-unresolved`）则留在配置页，因为那里才是唯一安全的复核入口。CSS 只隐藏 `.sidebar`，不删除节点；配置页在无工作空间时只提供「退出应用…」（走应用自己的退出确认与运行进程排空），有工作空间时（从设置页重进）才是「返回工作空间」。首启点「完成」后，启动记录已变成 `complete`，配置页随即被撤下、菜单与当前业务页当场绘制，用户不需要再关一次页。

运行进程的排空接口与退出门禁已实现并有隔离验收：无法确认进程停止或临时资源清理完成时，应用保持驻留，不强制退出。已确认所有权的资源清理失败可以重试；资源身份未能确认或路径已被替换时拒绝自动删除，需要人工检查。离线结果保留为待同步，不冒充已提交成功。

## 产品边界

- Electron App 自己管理中台和执行机运行进程，支持“中台 + 本机执行机”和“纯执行机”，不是遥控另外安装的系统服务。
- Electron 负责窗口、菜单栏、凭据与有限桥接；业务仍通过中台协议执行。内核不认识 Electron，不增加运行时依赖。
- 安装包目标为 macOS `.app` / `.dmg`，自带验证通过的 Node 24 与 TS 运行资源；不要求用户另装 Node。Agent CLI 仍需安装并登录。首期不承诺 Windows、自动更新、签名或公证。
- App 使用独立数据目录，不自动导入 CLI 数据，不安装 launchd/systemd，不修改全局 Skill 链接。CLI 安装与运行方式继续保留。
- 关窗只是隐藏窗口，运行进程继续工作；真退出确认后停止本机正在执行的 Agent，保留记录及待同步回执，不取消远程任务和中台尚未领取的队列。
- 纯执行机仅展示本机执行摘要、环境与连接，不保存 owner 密钥、不读取全局任务、不提供全局管理操作。摘要不等于中台队列。工人密钥只能读到本机自己的工作，运行进程的观测也刻意不带 run id、路径或令牌，因此中台执行记录对纯执行机不是"尚未加载"，而是设计上不可达：它的「本机任务」页只显示本机运行进程自报的持有量，并写明记录在中台所在设备查看，不渲染一个永远填不满的空列表。
- 已配置的角色不能在应用内覆盖或切换：改写会丢弃本机已有凭据且不可撤销，所以界面只如实说明"已有配置"，不提供一个会被拒绝的入口。旧配置（早于自动启动功能的机器）不会被自动启动，可以手动启动；要改为自动启动，必须移除本机配置数据后重新完成首次配置。
- 本期不开发插件管理页面或新的插件机制；现有 Agent、来源、通道插件加载路径和协议继续保留。

## 原型与真实功能的区别

原型是假的演示状态机。正式实现保留布局和操作组织，但不能复制下列假行为：

| 原型表现             | 正式实现                                                                                                                          |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 回答后原轮恢复执行   | 提问轮已结束；同轮 ask 全部已回答或正式关闭后，将全部已回答事件合入一次续办，尽量接续会话；部分回答只记录，全部关闭且无回答不派发 |
| 任意任务都能更正     | 只有存在可接会话且规则/Agent 匹配的轮次可更正；旧轮记录保留                                                                       |
| 点击停止即显示已停止 | 已领取轮次先显示正在停止，等待执行机确认进程组结束                                                                                |
| 模拟开始、完成、修复 | 不出现在正式界面；执行由 worker 和 Agent 回执驱动，首启只选择角色并写入连接配置                                                   |
| 固定三种任务路由     | 候选和路由来自真实 local 规则，输入不能决定 Agent、目录或权限                                                                     |
| 固定成本和比例       | 使用真实 usage；未上报不当作零，不估算输入/输出比例                                                                               |
| 默认目录属于 Agent   | 工作目录属于规则；编辑保留 group、parallel、tell、emits 等字段                                                                    |
| 交付反馈只改网页     | owner 限定的只记录事实：只写入反馈，不更正、不派发、不改变轮次结局                                                                |
| 远程机器平台和修复   | 只展示已有真实心跳与任务分配，不编造远程环境信息                                                                                  |

“任务”表示有独立身份的业务事情，不等于调度 lane 或执行 run。一件任务一张卡，原始标题与详情固定来自 origin_event_id；回答续办、占用释放和明确完成沿用[协议](protocol.md)。done 只结束一轮，不能推断业务完成或验收。缺详情区分未填写、历史缺失与中台未提供。

任务列表只显示业务任务，不保留业务/历史执行切换、旧记录入口、搜索框、已加载条数或加载更多按钮。请求 `GET /v1/ui/business-tasks?scope=business`，响应 scope 确认中台能力；身份过滤及 rule/state 组合在服务端分页前完成，每页默认 20 条，上一页/第 N 页/下一页居中且替换列表。旧执行不占用业务页、不删除数据，已完成、本人完成及取消任务仍按状态筛选显示。

标题下为同行工具栏：左侧横向规则导航占剩余宽度，右侧状态下拉固定。默认全部规则；目录来自全部业务任务，排除旧执行独有规则，独立于状态和分页，稳定排序。完整名精确筛选，切换规则或状态回第一页并保留另一条件；选中项无任务仍保留。规则不换行、长名限宽省略，title 与辅助名称保留完整名称；溢出左右按钮、触控板横向滚动，边界禁用，无溢出隐藏。明确焦点与选中状态，键盘切换选中项滚入可见范围。窄屏只缩小规则区，状态仍同行且不参与滚动，不造成全页溢出。

进入列表立即查询，可见每 5 秒刷新；详情、其他页面和窗口隐藏暂停，恢复可见立即刷新。保留筛选、页位置、列表和规则栏横向滚动；返回详情刷新原页恢复位置。请求串行、迟到结果不覆盖新筛选，失败保留列表并提示。不确定写入需显式重读核实，自动列表刷新不解除限制。

业务列表卡片展示任务标题、原始详情、状态、辅助信息与待决策问题，不展示当前进展、最终结果或本人验收原因；结果保留在详情记录与既有只读响应。整卡非操作区域点击进入详情，标题支持键盘 Enter；控件点击、修饰键、文字选择及未核实写入保护不变。详情头部与操作区按下述层级升级；保留原始需求、执行过程、交付结果、操作、事实时间线及关联执行历史。原 `/v1/ui/task-runs` 与 legacy 查询保留，但旧执行详情导航在桌面安全返回业务列表并简短提示，不展示旧记录、不猜关联。execution 只显示已记录轮次状态，done/nothing 不表示任务完成，stopping 且 claimed/unknown 仍等退出、不能重复停止。

旧中台没有业务接口时提示升级查看业务任务，绝不 taskList/taskDetail 降级展示旧执行。旧业务响应没有 scope 确认或全量规则目录时提示升级使用规则筛选，仅展示可确认业务记录和原服务端状态筛选，不从当前页拼规则或局部过滤冒充全局筛选，不有界扫描冒充完整业务分页。失败、不支持、空列表明确区分。数据与调度不变，严格 DTO 与[协议](protocol.md#业务任务身份与生命周期)同步。

### 本机 Agent 会话历史

业务详情遵循 desktop-ui-guide：全宽透明工作区，不叠整页面板外框；返回、原始标题与状态同行，顶部正文默认三行且按实际溢出展开。下方统一为任务记录卡片，不设执行过程／交付结果 Tab，不重复轮次汇总，不提供原始事实入口或显示事实编号。每个事实一张卡，按 kind 区分领取与开始，不把中间快照拆成节点。收到任务使用 display.events 的真实完整标题与详情，在同一个浅灰子卡保留换行，缺失与响应截断如实提示。开始卡提供对应真实执行编号的「查看执行会话」入口，原位进入独立只读子页面；返回保留任务详情节点、草稿和滚动位置，再返回沿用任务列表或今天的来源导航。子页明确 Agent 名称、执行编号、已记录状态和「关联会话历史，可能包含多轮」范围，未记录身份资料不猜测。执行诊断保留在详情折叠区，长会话不重复放在折叠区。方案卡使用 display.cards 的实际问题、选项及当前真实选择，等宽按钮，历史已选择用勾选、绿色边框和文字标记，其余禁用；旧响应缺结构化历史不猜选项。完成卡只展示一次结构化收尾正文，done 与明确任务完成、本人成果确认分别显示；反馈在关联 done 轮次卡内右下角，点击原位展开三选一反馈表单，只记录评价不重跑。分页、本人确认完成、暂停与恢复整件任务、取消整件任务、更正和未核实写入重读均保留；不可用入口隐藏，不显示完成阻塞提示。操作区位于需求下、记录上，当前进展在上（暂停中与取消中带过渡强调），调整类按钮在左（恢复执行为主操作、更正任务带草稿提示、暂停任务采用两步确认）、收尾类在右（本人确认完成与弱红文字取消）；各操作面板保持互斥，支持重复点击或 `Esc` 收起且保留草稿，表单支持 `Cmd/Ctrl + Enter` 快捷提交，弹窗提供「暂不提交」并拦截空提交。待回答时完整独立问答卡替代进展与调整/完成入口，真实选项突出显示并标注「推荐」徽章，纯文字／「其他想法」收为紧凑次级选择，取消保留；主操作与时间线的开放问题复用同一回答表单。选择只选中，不立即提交；输入框提示「补充说明或其他要求」，选择或输入即时清除校验提示，独立「提交回答」支持选项加文字、只选项或纯文字，空回答不能提交。客户端「其他想法」需字并作为纯文字发送；不凭实际选项的文字猜必填。选项和文字草稿按任务及卡片身份保存，两处入口共享草稿，普通权威刷新不清空；写入中禁重复，结果不确定保留草稿并要求显式重读核实，自动刷新不能解除保护。已回答显示真实选项与补充文字，不篡改原回答、不推断恢复或代答其他卡片。完成与取消必填原因并二次确认，更正依赖中台 correctTask 只读能力，completed 仍可按真实会话及规则条件更正、queued 不可更正。可见详情每 5 秒读取，进入与窗口恢复可见或焦点时核实；普通手动刷新移除，自动核实不解除不确定写入保护。后台自动核对采用静默差异更新策略：读取飞行期间保持已有操作按钮、输入框与诊断就绪态稳定，不闪烁禁用态或清空既有错误提示，也不阻塞用户发起写入（写入发起时使飞行中的旧后台读取失效）；若数据与运行诊断均无变化则不触发视图更新。存在真实变化时仅局部更新变动字段，已展开的顶部需求正文不反复收起重测，隐藏中的任务列表不重复重建；时间线在连续衔接时保留已翻页加载的更早记录，并按事实序号增量插入或仅修补发生变化的单条记录，保留既有卡片节点、触发/交接详情展开态、文字选区与活跃输入焦点；查看执行会话子页时同样保持头部控件稳定，不重置 2 秒增量轮询。写入飞行、待核实与不新鲜详情禁重复提交。表单草稿常驻，关闭更正弹窗保留未提交内容，不因普通状态通知清空输入。原始需求、普通进展与明确收尾结果不互相替代。

时间线可选 `display.reviews: { items, truncated }` 按同任务的 timer 事实展示当时安排、触发或取消，finish 内在同一记录增加独立复查区，不拆假节点；取消从该 timer 的索引历史读取原安排，当前状态仅核验同 taskId 的投影或明确删除事实，缺历史为 unknown。items 最多20项，每项 `{id,key,at,about,action,state,truncated}`，key/about 最多200/1000码点；action 为 scheduled/triggered/cancelled，state 为 pending/triggered/cancelled/unknown。到点待执行仅是本机时间对 pending 的显示提示，不证明触发；已触发不证明业务核实完成，结果仍看后续事实。历史改期保留当时时间和内容，当前状态单独显示；纯文字、长文展开、数量及文字截断明确。空数组表示本事实未记录复查，旧响应缺字段明确未提供能力，不造数据。SQL 字段及数量有界，单项资料预算最多1200码点，每节点最多24000码点；沿用单节点和详情128 KiB预算的截断/省略与游标推进规则。严格拒绝额外字段的旧客户端需与中台同步升级，新客户端接受缺字段旧响应；不改变调度、日志、写接口，不迁移历史。

复查区使用原事实卡内的轻量分隔线，不再嵌套重型卡片。历史动作标题（已安排复查／本次复查已触发／已取消复查）、当前状态标签与复查时间分开，复查标识如实展示以区分多项；触发事实不重复兼容诊断长文，不把触发称为验收。交接资料无论长短统一默认收起，入口为「查看交接详情」，展开后为「收起交接详情」，原位完整纯文字保留换行并让长路径断行，不用原文片段充当入口标题。普通刷新及时间线增量更新保留同任务、同事实、同复查的展开状态，不串到另一事实或任务。没有可靠执行关联时不造跳转或执行状态，旧响应及截断提示沿用原约定。

领取卡仅在 claim/claimNext 使用可选 `display.trigger`，按事实 runId 复用今天页 request/triggers 的真实关联与摘要规则；显示「本轮触发资料」次级纯文字区，超过 160 码点折叠并可展开。历史回答没有提交控件，started 不显示此区，旧中台缺字段保留原卡。中台与桌面需同步更新以获得新资料字段，固定原始需求及既有预算不变。

`desktop:agent-history:read` 只接受 runId 与可选 attempt、launch、opaque cursor。主进程先通过既有本人查询验证执行存在，沿用发送者核验与可撤销租约；读取 App 自己管理的本机运行目录，或经过安全 CLI 配置检查与本人鉴权的挂接本机目录；远端 worker 不支持。挂接逐次核对固定 loopback 端口、CLI 配置的本机 worker URL 与凭据，沿用祖先目录及配置文件的有界 no-follow 检查；Claude 默认根目录来自系统账号 home，renderer 不能提供目录。读取前后重新核对目录与连接指纹。runs.attempts 是失败重试次数：非 queued 执行的编号为 attempts + 1，queued 只可读取已经失败的 attempts 次执行，不猜旧关联。连接指纹绑定固定 URL、worker 凭据与本机 hub.db 的文件身份，换中台文件不能复用旧关联；仅留在主进程/本机元数据，不交给页面。worker 在新启动时保存 `worker/history/<run>-<attempt>.json`，仅含执行关联、Agent、工作目录和启动会话；该目录不在交给 Agent 的资料目录内，也不随 entry 删除或运行目录的 14 天清理一起删除，不复制 JSONL。旧启动缺关联时不可读，不扫描用户所有会话来猜关联。

历史能力是 Adapter 的可选接口，只实现 Claude 默认本机配置目录的主会话 JSONL；自定义 launcher、CLAUDE_CONFIG_DIR、Codex、侧链和远端均不支持。页面按任务详情风格展示 Agent 文本、普通 user 文本及独立工具卡，tool_use 与 tool_result 只按真实 tool_use_id 关联，不按顺序猜配对。system、thinking、meta 与 sidechain 不展示。本机原始参数与结果可能含私密资料，仅经过可信身份核验的本机页面展示，不上传、不进入提示词、不按凭据文字静默丢记录。普通 user string 和 text array 均保留；任务输入只在文字的 SHA-256 与 worker 保存的可信启动 inputHash 完全一致时标记，旧关联缺 hash 不猜。hash 只是展示归因，不授予任何权限。

单次文件读取最多 10 MiB，单页最多 50 个 4000 字符片段，IPC 总计最多 256 KiB；长内容按片段自动分页并在原代码节点累积，预览与展开不替换旧节点。默认自动读完当前关联会话的完整行，不设手动分页或范围说明。会话仍可能包含多轮，不按时间猜分轮。页面累积最多 20,000 片段或 32 MiB 序列化资料，作为本机页面防止无界 DOM/内存的硬保护而非完整性承诺；达到任一上限明确报告尚未读取完整并保留已读记录，不能显示为已读完。单行超过 10 MiB 明确不可读，未完成末行等待追加、不越过游标；替换、截短或已观察原地修改停止读取。每页顺序单飞，离页、隐藏或身份撤销取消后续页及轮询，迟到响应不串页；运行中读完历史后每两秒读取新追加记录，不强制滚底。私有游标留在主进程，页面仅持有 opaque token；现有 trusted scope/path/lease 与静态打包读取能力不变。

HistoryItem 保留 id/kind/at/text/truncated，新增可选 role、toolUseId、name、error、part。新桌面接受旧条目，旧条目没有工具身份时不猜配对；严格拒绝额外字段的旧桌面需同步升级。启动关联新增可选 inputHash，不迁移旧日志或历史。真实 CLI 及时落盘与准确分轮仍未通过付费调用验收。

### 保留的执行轮次诊断与旧中台兼容

执行记录列表走独立通道 `desktop:tasks:list`，直连中台 `GET /v1/ui/task-runs`，与今天页、托盘用的 `desktop:tasks:get`（`GET /v1/state` 投影）是两条门：前者是可带游标的分页查询，后者是整机快照。`q/state/rule/agent/source/type` 全部在服务端求值，界面不会先取一页再本地过滤；空字段整项省略，不发送空过滤值。`q` 只匹配任务摘要与失败原因（`summary` 与 `error` 两列，`%`、`_` 已转义），界面在筛选栏就写明这一点，不暗示它会搜索正文、事件或卡片。默认一页 30 条、上限 60 条，严格按 `id` 降序；返回 `hasMore` 为真时 `nextBefore` 恰为当页最后一条的 `id`，界面只把这个游标当下一页的 `before` 传回去，从不自己推算。中台每一页都会重复当前仍在推进的轮次，所以追加时按 `id` 去重，已在屏幕上的那条不会被新页改写。切换关键词或状态会从第一页重读；旧查询的迟到回包被丢弃，不会混进新过滤的结果，也不会被当成分页追加。

列表项按「任务标题、单行任务详情、执行结果」分层，标题与正文来自本轮关联的最新事件（事件 id 最大者），不能用规则名或执行摘要冒充任务标题；规则、执行体与时间退到辅助信息。列表响应的 RunItem 可选增加 `preview: { title, detail, truncated, decisions }`，旧响应没有 preview 时明确显示未记录标题与详情，结果仍使用真实 `summary/error` 或执行状态。标题最多 500 字、正文最多 2000 字；`decisions` 使用卡片分页结构，最多展示本轮自己的 3 张开放提问，按卡片 id 降序，不混入已回答问题或通知。更多决策用 `hasMore` 如实提示进入详情查看；preview 游标不用于列表内写入或直接回答。决策文字不做界面省略，保留问题与全部已返回选项；仍遵守中台已有卡片文字和选项边界，源文字被截断时单独注明，不声称看到了源数据全文。整个列表仍受 160 KiB 预算约束，不逐项读取完整详情。

任务详情与列表共享主容器，以「← 返回」原位切换，不再使用行内手风琴。返回保留规则/状态筛选、当前页及滚动位置，刷新原页而不重读第一页。详情按真实轮次展示中台已保存的结果摘要、失败原因、事件正文、卡片及回答；关联轮次可按需读取自己的详情。`GET /v1/ui/task-runs/:id` 的摘要和失败原因最多 500 字，截断时注明。完整 Agent 对话、工具调用与执行机 stdout/stderr 没有中台读取接口，页面明确说明未记录到中台，不能将摘要拼成虚构对话。正文为纯文字，不执行其中的标记。详情表单节点独立常驻，分页、反馈读取和同轮重读不拆掉输入节点；写入仍遵循单飞与结果不明重读约束。

## 本机任务入口协议

桌面规则与任务桥接 DTO 为版本 2，规则编辑使用版本 3 的 CAS 外壳；主进程与 renderer 同步校验；HTTP 仍兼容已有网页的 `GET /v1/ui/rules` 与数组 `PUT /v1/ui/rules`。列表可以为空，表示移除所有 local 入口，不移除其他来源规则。

- 入口有两种触发：事件入口带 `types`，定时入口带 `cron`（五字段 cron，同一解析器在两边校验）；一个入口只能有一种触发，同时带两者在中台保存前就被拒绝。定时入口在磁盘上声明为 `when: { "cron": "...", "local": true }`，与事件入口的 `source: "local"` 一样只标记插槽归属，不改变定时何时跑。
- 其余字段为 `name/to/cwd`，可选 `prompt/skill/parallel/group/tell/emits`；`emits` 严格为 `{source,types}`，来源必须已登记且不能为保留的 `schedule`。表单可保留、修改或清除高级字段。
- 未声明 `group` 时跟随规则名称，未声明 `tell` 时使用 `needed`。显式 `group` 即使等于旧规则名称也会保留，不从解析后的默认值反推用户意图，不新增 `defaults` 元数据。
- 替换原有 local 插槽，不挪动非 local 规则；新增项放在最后一个 local 插槽后，无原有 local 时追加。保存对同一份文件执行一次读取、合并、完整校验和原子替换，缺失的 local 来源一并补齐。无效来源引用不落盘。
- 候选规则支持 `*` 和 `x.*`；真实事件仍只接受小写字母开头、最长 64 字符的具体类型。选择通配模式必须手动填写匹配的具体类型，不自动生成后缀；最终路由以中台回执为准。
- 原始声明仅在完整校验且与中台已应用配置一致时用于编辑。坏磁盘或尚未生效的变更不混入旧运行配置。内核历史只保存解析后的有效值，未持久化原始声明；冷启动遇到坏磁盘且没有有效声明快照时明确拒绝编辑，不能无条件恢复历史显式字段。

交付反馈只记录事实，不产生新一轮：`POST /v1/runs/:id/feedback` 需要 owner 密钥，只接受 `state === "done"` 的轮次，`kind` 为「交付满意 / 需要改善 / 内容错误」三选一，`text` 去空白后非空且不超过 4000 字。写入只追加一条反馈，不投递事件、不开卡片、不入队、不改变该轮已有的结局或成本记录。读取走 `GET /v1/ui/task-runs/:id?section=feedback`，是与事件、卡片、关联记录并列的第四组独立分页段，用各自的游标推进；反馈不进入详情快照，详情首屏不会被历史反馈撑大。桌面在主进程与 renderer 两层都校验同一套动作契约，与回答、结案、停止、更正共用“单次发送、结果不明先重读”的写入窗口。

自动化页使用 `rulesCasGet`/`rulesCasPut`：读取返回 `entries/agents/seq/rulesSeq`，保存提交 `{entries, rulesSeq}`，`rulesSeq` 是草稿开始编辑时的规则版本，不是日志序号。列表页提供触发方式筛选（全部／事件触发／定时触发）、整行点击编辑、中文定时节律与执行体名称展示及空态添加入口；新增、编辑与删除统一在原位子页中直接提交 CAS 保存（无改动时直接返回不发写请求，删除采用右下角两步确认防误触）。中台在版本不匹配或结果不明时拒绝静默覆盖，子页保留用户输入与错误提示并锁定写入，仅通过「丢弃修改并重新读取」解除屏障。主进程对同一时刻只放行一次保存，文档切换或页面重载会使迟到回执失效。手工派发的候选列表只投影事件入口——定时入口没有类型可派，跳过而不是让整页读取失败。非 local 自动化编辑仍未实现，原因是缺一条能读回它们的通道，而不是中台拒绝：桌面入口 DTO 只建模 local 入口（事件入口扁平 `types`，定时入口带 `cron`），其它规则用的是 `when.source` 或 `when.cron`，`elsewhere` 又是另一套字段；设置页的配置投影刻意丢弃 `rules` 与 `elsewhere`，CAS 也只返回 local 入口。没有读取就没有编辑——硬加一条只写通道，等于让桌面去替换它从未见过的规则，并把 local 插槽的合并语义在第二处重写一遍，两条编辑路径会慢慢分叉。中台自己的整段 `rules` 写入同样受 `rulesSeq` 与磁盘声明哈希约束，不会静默覆盖并发修改；这类规则继续在中台网页控制台（`http://127.0.0.1:3350`）修改，自动化页在说明里写明这一点。

设置页的 Agent、来源与通知通道新增与编辑统一使用原位子页，返回回到对应分组；切换导航保留草稿与表单节点，删除采用两步确认防误触，保存成功返回列表，冲突与结果不明保留编辑屏障。通用页提供主题分段切换与时区、确认事项的直接内联编辑；角色连接页以结构化卡片展示角色状态与终端凭据命令。

设置页使用 `settingsGet`/`settingsPut` 读写 `GET /v1/ui/config` 与 `PUT /v1/ui/config/:section`：可编辑分组为 `agents`、`sources`、`channels`，以及 `settings`（时区与确认事项）。草稿固定在开始编辑时的 `rulesSeq`，整组替换而不是逐条补丁，保存冲突或结果不明都成为屏障，只能通过“丢弃草稿并重新读取”清除，且该动作在重新读取成功前不会解除。主进程与 renderer 共用同一份 `host/desktop-settings-contract.ts`（键集、长度、字段取值、128 KiB 上限、固定文案），主进程对同一时刻只放行一次读写，每次飞行重新读取本机配置，迟到响应被丢弃。凭据只能由 CLI 写入和列出，界面不读取、不显示、不保存任何明文密钥；纯执行机只显示连接说明，「角色连接」分组只能查看本机配置状态，不提供覆盖或切换角色的入口。
